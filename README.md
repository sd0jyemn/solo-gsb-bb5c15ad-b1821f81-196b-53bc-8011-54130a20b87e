# 合唱视线遮挡检查台（Choir Sightline Checker）

在平面舞台上拖放**指挥**与**圆形站位**、调整人体半径，系统实时判断每位演唱者到指挥的视线线段是否被其他站位圆遮挡，按**沿视线最近的遮挡者**着色，并列出全部受阻关系。前后端共用同一套几何判定核心，支持场景 JSON 导入/导出与服务端校验。

## 快速开始（单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**（服务端口 `8080`，可用 `PORT` 环境变量覆盖；Compose 已将宿主 8080 映射到容器 8080）。

> 若使用旧版 Docker Compose：`docker-compose up --build`。

镜像构建过程会自动完成依赖安装（`npm ci`）、几何核心单元测试与前后端构建；运行阶段为仅含构建产物的精简镜像，无需 node_modules。

## 功能

- **拖放编辑**：拖动指挥（▲）与站位圆调整位置；双击舞台空白处添加演唱者；点击选中后用滑杆或**滚轮**调整人体半径（0.10–1.00 m）。
- **实时判定**：每次修改即时重算全部视线，绿色=通畅、琥珀色虚线=相切擦边、彩色=被遮挡。
- **最近遮挡者着色**：被遮挡者的填充色与其**沿视线最近遮挡者**的身份色一致（侧栏列表与站位圆描边的彩色圆点一一对应），并在线段上标出进入点。
- **受阻关系列表**：逐条列出「谁 → 指挥 被谁遮挡（进入距离、侵入深度）」，共线时的其余遮挡者、相切与退化情况单独分组。
- **JSON 导入/导出**：导出当前场景为 JSON 文件；导入时完整校验并给出全部错误。
- **服务器校验**：一键将场景 POST 到后端 `/api/analyze`，与前端结果比对（两端共用 `shared/geometry.ts`，结果必然一致）。
- **测试预设**：工具栏可载入「共线测试」「相切测试」「重合测试」等边界场景。

## 判定规则（精确语义）

视线定义为**演唱者眼睛（站位圆圆心）到指挥点的线段**，其他站位圆按线段-圆相交判定：

| 情形 | 条件（d = 圆心到线段距离，r = 半径） | 结果 |
| --- | --- | --- |
| 遮挡 | d < r − ε | `blocked`，按进入参数 t 最小者为最近遮挡者 |
| 相切 | \|d − r\| ≤ ε | `tangent`（擦边，**不**判为遮挡，单独标注） |
| 通畅 | d > r + ε | `clear` |
| 退化 | 演唱者与指挥距离 < 1e-9 m | `degenerate` |

- 容差 ε = `TANGENT_EPS = 1e-6` m（见 `shared/geometry.ts`），保证相切边界判定确定、不抖动。
- **重合**：站位圆包含眼睛或指挥时按相交处理（进入参数钳制到 0/1）；圆心重合的站位、与指挥重合的站位会在警告区单独列出。
- **多人共线**：全部遮挡事件按沿视线进入参数 `tEnter` 升序排列，最近的非相切遮挡者决定着色，其余遮挡者在受阻关系中列出。

## 本地开发

```bash
npm install        # 安装全部工作区依赖
npm run dev        # 并行启动后端(8080)与前端 Vite(5173，代理 /api)
```

访问 http://localhost:5173 进行热更新开发。

其他脚本：

```bash
npm test           # 几何核心单元测试（相切/重合/共线等边界）
npm run typecheck  # 前后端 TypeScript 类型检查
npm run build      # 构建前端(client/dist)与后端(server/dist)
npm start          # 生产模式启动（http://localhost:8080）
```

## JSON 场景格式

```json
{
  "version": 1,
  "stage": { "width": 12, "depth": 8 },
  "conductor": { "x": 6, "y": -1.5 },
  "singers": [
    { "id": "s1", "name": "S1", "x": 3, "y": 2, "radius": 0.3 }
  ]
}
```

- 单位为米；舞台左上角为原点，y 向下为舞台纵深，指挥可位于 y < 0 的舞台前方区域。
- 校验规则：半径 0.05–1.5 m，舞台宽 2–40 m、深 2–30 m，演唱者 ≤ 500 人，id 唯一。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| POST | `/api/analyze` | 请求体为场景 JSON，返回 `{ ok, analysis }`（每位演唱者的状态、按距离排序的遮挡事件、警告与统计）；非法场景返回 400 及全部错误 |

## 项目结构

```
├── shared/geometry.ts        # 几何判定核心（前后端共用）+ 场景校验
├── shared/geometry.test.ts   # 单元测试：相切/重合/共线/退化等
├── server/src/index.ts       # Express：静态托管 + /api/health + /api/analyze
├── client/src/               # React + SVG 舞台（拖放/滚轮/实时着色）
├── Dockerfile                # 多阶段：构建(含测试) → 精简运行时
└── docker-compose.yml        # 单服务，端口 8080
```
